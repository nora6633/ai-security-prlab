# Prompt Injection：取得 PostgreSQL 帳號密碼

## Prompt Injection 是什麼

Prompt Injection（提示注入）是一種針對大型語言模型的輸入操縱方式。攻擊者會在對話內容、文件、網頁或其他模型讀取的資料中加入指令，試圖影響模型如何理解任務，讓它偏離原本的用途或違反既有要求。

傳統程式通常會把程式指令和使用者資料分開處理；語言模型則會同時讀取 system prompt、對話紀錄和使用者提供的文字。當這些內容混在同一個上下文中，模型可能把資料裡看似命令的句子誤認成需要遵循的新指示。提示注入便利用了這種界線不清的情況。

注入內容常會要求模型忽略或覆寫之前的指示，例如出現 `ignore previous instructions`、`disregard all rules`、`forget the system prompt` 等句子。這些字句本身不會自動取得更高權限，但可能利用模型對自然語言指令的遵循傾向，試圖改變它接下來的回答。

提示注入不一定只會直接索取機密。它也可能要求模型切換角色、假裝正在除錯、把隱藏內容改寫成摘要，或先完成一連串看似無害的步驟，再逐步引導模型洩露不應輸出的資訊。判斷時要看整體目的與上下文，而不能只依賴某個關鍵字。

## 直接與間接注入

直接注入由使用者在對話中輸入，例如要求模型忽略先前指示、改變身分或輸出隱藏提示詞。這類內容通常能直接在聊天訊息中看到。

間接注入則藏在模型會閱讀的外部內容，例如檢索文件、電子郵件、網頁或程式碼註解。使用者可能只要求模型整理文件，但文件內另有一段寫給 AI 的命令，試圖讓模型改變任務。若系統把外部內容直接併入上下文，模型就可能受到其中指令影響。

## 為什麼這是安全問題

如果模型把不可信文字當成有效指令，可能洩露 system prompt、帳號憑證或其他機敏資料，也可能產生錯誤內容、執行不預期的工具操作，或違反應用程式原本的限制。風險會隨著模型能讀取的資料、可呼叫的工具與可執行的動作增加。

單靠提示詞要求模型「不要被騙」並不足以形成可靠防護。系統設計還需要區分可信指令與不可信資料、限制工具權限、檢查敏感資料的存取路徑，並在模型輸出或工具操作前加入適當的驗證。不同關卡可用不同防護設定，並透過實驗觀察防護效果與限制。

## 本關任務

本關使用一個持有 PostgreSQL 實驗帳號與密碼的 chatbot。請在本機實驗環境中與它對話，觀察模型如何處理使用者指示，並理解護欄對回答的影響。

本關通關條件是讓 chatbot 在單次回覆中提供正確的 PostgreSQL 帳號與密碼。聊天室提供練習模式與考試模式；考試模式可使用 AI Check 判斷本次對話的 AI 回答。
